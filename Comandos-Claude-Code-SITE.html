Guia Completo dos Comandos do Claude Code

Referência em português de todos os comandos: barra (/), terminal (claude …), atalhos de teclado e modos especiais. Baseado na documentação oficial (v2.1.x).

💡 Dica: clique em qualquer comando (1ª coluna das tabelas) para copiá-lo. Depois cole com Ctrl+V no Claude Code — no Terminal, no VSCode ou no navegador, onde você estiver trabalhando.

⚙️Configuração e início de projeto

Comandos digitados no início da mensagem, dentro do Claude Code. <arg> = obrigatório · [arg] = opcional.

ComandoO que faz
/initCria um arquivo CLAUDE.md inicial documentando o seu projeto (guia para o Claude).
/memoryEdita os arquivos de memória CLAUDE.md; liga/desliga a memória automática e mostra suas entradas.
/config [chave=valor]Abre as configurações (tema, modelo, estilo de saída…). Pode setar direto, ex.: /config theme=dark. Apelido: /settings.
/permissionsGerencia regras de permissão (permitir / perguntar / negar) das ferramentas. Apelido: /allowed-tools.
/agentsCria e gerencia subagentes de IA (delegação de tarefas).
/mcpGerencia conexões com servidores MCP e autenticação OAuth.
/hooksVê e configura os hooks (ganchos) que disparam em eventos de ferramentas.
/skillsLista as skills (habilidades) disponíveis; permite ocultar alguma.
/plugin [subcomando]Gerencia plugins (list, install, enable, disable…).
/reload-plugins [--force]Recarrega plugins sem reiniciar.
/reload-skillsRe-escaneia skills/comandos adicionados durante a sessão.
/statuslineConfigura a barra de status do Claude Code.
/keybindingsAbre o arquivo de atalhos de teclado para personalizar.
/themeMuda o tema de cores (claro, escuro, automático, daltônico…).
/terminal-setupConfigura o atalho Shift+Enter (nova linha) no seu terminal (VS Code, Cursor etc.).
/ideGerencia a integração com a IDE e mostra o status.

⏱️Durante a tarefa

Comandos do dia a dia enquanto o Claude trabalha.

ComandoO que faz
/plan [descrição]Entra no modo de planejamento (planeja antes de executar). Ex.: /plan corrigir o bug de login.
/model [modelo]Troca o modelo de IA (Opus, Sonnet, Haiku, Fable) e salva como padrão.
/effort [nível]Ajusta o "esforço" de raciocínio: low, medium, high, xhigh, max, ultracode.
/fast [on|off]Liga/desliga o modo rápido (mesmo Opus, com saída mais veloz).
/context [all]Mostra o uso do contexto (janela) num grid colorido, com dicas de otimização.
/compact [instruções]Resume a conversa para liberar contexto. Pode focar o resumo em algo.
/clear [nome]Começa uma conversa nova com contexto vazio (mantém a memória do projeto). Apelidos: /reset, /new.
/btw <pergunta>Pergunta rápida "a propósito" sem poluir o histórico da conversa.
/goal [condição]Define uma meta: o Claude continua trabalhando entre turnos até cumprir.
/recapGera um resumo de uma linha do que aconteceu na sessão.
/copy [N]Copia a última resposta do Claude (ou a N-ésima) para a área de transferência.
/export [arquivo]Exporta a conversa como texto (arquivo ou área de transferência).
/diffAbre um visualizador interativo das mudanças não commitadas e por turno.
/focusMostra só o essencial (seu último prompt + resumo das ações + resposta final).
/insightsGera um relatório analisando suas sessões (padrões, pontos de atrito).
Nota: /plan × Shift+Tab × /ultraplan — as três formas de planejar. Todas levam ao modo de planejamento (o Claude propõe um plano e só executa após sua aprovação). A diferença é só como você entra nele:
  • /plan [descrição] — comando que entra no modo já com a tarefa. Ex.: /plan corrigir o bug de login.
  • Shift+Tab — atalho de teclado que alterna para o modo de planejamento (sem digitar).
  • /ultraplan <prompt> — o "primo grande": rascunha o plano numa sessão na nuvem, você revisa no navegador e manda executar. Para tarefas maiores.

🔀Trabalho em paralelo e em segundo plano

Para rodar tarefas em segundo plano, ramificar ou orquestrar vários agentes.

ComandoO que faz

/tasksVê e gerencia tudo que está rodando em segundo plano. Também como /bashes.
/fork <diretriz>Cria um subagente que herda a conversa e trabalha numa tarefa enquanto você continua.
/branch [nome]Ramifica a conversa neste ponto para tentar outra direção sem perder a original.
/batch <instrução>(Skill) Decompõe uma mudança grande em 5–30 unidades e roda cada uma em paralelo (worktrees).
/loop [intervalo] [prompt](Skill) Roda um prompt repetidamente. Ex.: /loop 5m verifique se o deploy terminou. Apelido: /proactive.
/workflowsAbre a visão de progresso dos workflows (orquestração de vários subagentes).
/stopPara a sessão em segundo plano à qual você está conectado.

/verify(Skill) Confirma que a mudança funciona rodando o app de verdade (não só testes).

🐙Salvar no GitHub

Use o prefixo ! para rodar comandos Git/GitHub diretamente de dentro do Claude Code, sem sair da sessão. Requer gh CLI instalado (! gh --version para verificar).

Primeiro uso (inicializar e publicar)

ComandoO que faz
! git initInicializa o repositório Git local na pasta atual.
! git add .Adiciona todos os arquivos ao stage (prepara para o commit).
! git commit -m "mensagem"Cria o primeiro commit com uma mensagem descritiva.
! gh repo create nome --public --source=. --pushCria o repositório no GitHub e já faz o push num comando só (requer gh auth login feito antes).

Uso diário (salvar alterações)

ComandoO que faz
! git add .Marca todos os arquivos modificados para envio.
! git commit -m "mensagem"Registra as mudanças com uma mensagem.
! git pushEnvia os commits para o GitHub.
! git pullBaixa atualizações do GitHub para o PC.
! git statusMostra quais arquivos foram alterados e ainda não foram commitados.
! git log --oneline -10Lista os 10 últimos commits de forma resumida.

Integração com o Claude (CI/CD)

ComandoO que faz
/install-github-appInstala o app do Claude no repositório para revisar PRs e rodar correções automáticas via GitHub Actions.
claude setup-tokenGera token OAuth de longa duração para autenticação do Claude em pipelines de CI.
/autofix-prCria sessão na nuvem que vigia o PR e envia correções quando o CI falha.

▲Deploy no Vercel

Use o prefixo ! para rodar o Vercel CLI dentro do Claude Code. Na primeira vez será pedido login no navegador. O projeto precisa estar no GitHub para deploy contínuo.

Primeiro deploy

ComandoO que faz
! npx vercelInicia o deploy interativo: pede login (1ª vez), nome do projeto e configurações. Publica numa URL de preview.
! npx vercel --prodPublica direto no domínio de produção (sem URL temporária de preview).

Uso diário

ComandoO que faz
! npx vercel --prodRe-faz o deploy em produção com os arquivos atuais.
! npx vercel linkVincula a pasta a um projeto Vercel já existente (quando o projeto foi criado pelo dashboard).
! npx vercel env pullBaixa as variáveis de ambiente do Vercel para um arquivo .env.local.
! npx vercel logsVê os logs do último deploy.
! npx vercel lsLista todos os seus projetos e deploys no Vercel.
! npx vercel whoamiConfirma com qual conta Vercel você está autenticado.
Dica: conectar o repositório GitHub ao Vercel pelo dashboard (vercel.com) ativa o deploy automático a cada git push — sem precisar rodar o comando manualmente. Use ! git push e o Vercel faz o resto.

💜Deploy no Lovable

Lovable (lovable.dev) é um builder de apps com IA que importa projetos do GitHub. Não tem CLI própria — o fluxo é: salvar no GitHub → importar no Lovable.

Pré-requisito: projeto no GitHub

ComandoO que faz
! git add .Stage de todos os arquivos.
! git commit -m "versão inicial"Commit dos arquivos do projeto.
! git pushEnvia para o GitHub (repositório deve existir e ter o remote configurado).

Sincronizar mudanças com o Lovable

ComandoO que faz
! git add . && git commit -m "update" && git pushSalva, commita e envia tudo para o GitHub num comando encadeado. O Lovable puxa automaticamente se estiver conectado ao repositório.
! git log --oneline -5Confirma que os commits chegaram antes de abrir o Lovable.
Passos no navegador (só na 1ª vez):
  • Acesse lovable.dev → "Import from GitHub".
  • Autorize o acesso ao repositório do projeto.
  • Lovable importa o código e abre o editor com IA.
  • A partir daí, cada git push sincroniza automaticamente.

❗Modos especiais e prefixos

Caracteres no início da mensagem que mudam o comportamento.

Prefixo / teclaO que faz
/ (no início)Executa um comando ou skill.
! (no início)Modo shell: roda um comando direto, adiciona a saída ao contexto e o Claude responde a ela. Ex.: ! npm test, ! git status.

📝Modo Vim (edição estilo Vim)

Ative em /config → Editor mode. Principais comandos no modo NORMAL:

Trocar de modo: Esc (NORMAL), i/I (inserir antes/início), a/A (inserir depois/fim), o/O (abrir linha abaixo/acima), v/V (seleção visual).
Navegar: h/j/k/l (←↓↑→), w (próxima palavra), e (fim da palavra), b (palavra anterior), 0 (início da linha), $ (fim da linha), ^ (1º caractere não-branco), gg/G (início/fim), f{c}/F{c} (pular para caractere).

Tradução prática dos comandos que mais valem a pena no uso comum.

Conversa ficou enorme e lenta?

/compact → resume e libera espaço mantendo a conversa.

/clear → começa do zero (mantém só a memória do projeto). Use ao trocar de assunto.

/context → mostra "onde está indo" a memória, se quiser entender o consumo.

Quer ver quanto está gastando?

/usage (ou /cost) mostra custo e limites do plano.

Fechou e quer voltar de onde parou?

claude -c (no terminal) ou /resume (dentro). Para nomear sessões e achar depois: claude -n "meu-trabalho".

Errou e quer desfazer?

/rewind volta a um ponto anterior (checkpoint). É a sua "rede de segurança".

Quer planejar antes de mexer em tudo?

/plan (ou Shift+Tab até o modo plan). Ele propõe e só executa após sua aprovação.

Algo parou de funcionar?

/doctor diagnostica a instalação; /status mostra versão, modelo e conexão.

Rodar um comando do sistema sem sair?

Use ! na frente. Ex.: ! ipconfig.

Apontar um arquivo específico?

Digite @ e comece a escrever o caminho.

Nível de "capricho" da resposta

/model (troca o modelo) e /effort (quão fundo ele pensa). /fast deixa o Opus mais ágil.

Acabar a tarefa

/exit (ou Ctrl+D) para sair.
